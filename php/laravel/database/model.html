# Primary Keys

<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Product extends Model
{
    /**
     * The primary key associated with the table.
     *
     * @var string
     */
    protected $primaryKey = 'product_id';
	
    /**
     * Indicates if the model's ID is auto-incrementing.
     *
     * @var bool
     */
    public $incrementing = false;

    /**
     * The data type of the auto-incrementing ID.
     *
     * @var string
     */
    protected $keyType = 'string';	
}

# Timestamps

<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Product extends Model
{
    /**
     * Indicates if the model should be timestamped.
     *
     * @var bool
     */
    public $timestamps = false;
	
	/**
     * The storage format of the model's date columns.
     *
     * @var string
     */
    protected $dateFormat = 'U';
	
	// Customize names
	const CREATED_AT = 'creation_date';
    const UPDATED_AT = 'updated_date';
}

# Dynamic model defaults with defaults()

Laravel 13.35.0 adds an opt-in defaults() method through the HasDefaultAttributes trait. See Laravel News (opens new window) and framework PR #61813 (opens new window). Unlike static $attributes, the method can derive defaults from configuration, feature flags, or the current date.

namespace App\Models;

use Illuminate\Database\Eloquent\Concerns\HasDefaultAttributes;
use Illuminate\Database\Eloquent\Model;

class Subscription extends Model
{
    use HasDefaultAttributes;

    protected function defaults(): array
    {
        return [
            'cancelled' => false,
            'trial_days' => config('billing.default_trial_days', 14),
        ];
    }
}

The returned values are raw defaults: they take precedence over $attributes and skip casts and mutators. Use this trait only on models that intentionally opt into the behavior.

Introduced in: Laravel Framework v13.35.0, PR laravel/framework#61813.

Sources: Laravel News — Laravel 13.35.0 (opens new window), framework PR #61813 (opens new window).
